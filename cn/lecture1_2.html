Core Principles

Vibe Coding 四大核心原则

1. Intent over Syntax

传达意图比语法更重要

// 差的提示 "用 for 循环解析 FASTA" // 好的提示 "提取 GC content > 60% 的序列"

2. Small Steps

以小步骤迭代

// 差的提示 "把整个流程都做出来" // 好的提示 "Step 1: 解析 PDB → Step 2: ..."

3. Context is King

提供丰富的上下文

// 数据类型、格式、大小、 // 期望的输出、使用的库 // 全部包含在提示词中

4. You = Reviewer

你就是审查者

// AI 生成 → 你来验证 // 特别是生物学合理性！ // EGFR score > TP53 对吗？
Prompting

好的提示词 vs 差的提示词

Bad Prompt

"帮我分析基因" "跑一下对接" "画个图"

× 模糊，缺少上下文，AI 只能猜测

Good Prompt

"从这个 CSV 的 Gene Symbol 列中 读取基因列表， 通过 Enrichr API 进行 GO enrichment 分析，然后将前20个画成 barplot。 以 p-value < 0.05 为标准。 使用 pandas + matplotlib。"

✓ 具体、上下文丰富、指定工具

Template

提示词模板

[角色] 我是一名生物信息学研究生。 [背景] 我正在分析 RNA-seq 数据。 DEG 列表包含 1,200 个基因。 是 HepG2 与正常肝细胞的对比实验。 [目标] 我想做 GO enrichment analysis。 [具体] - 使用 enrichR API - GO_Biological_Process_2023 数据库 - 前 20 个 pathway 的 barplot - p-value < 0.05 [输出] DataFrame + PNG (300 DPI) [约束] 仅使用 pandas, matplotlib, requests

中文提示词完全没问题！但技术术语混用英文时准确度更高

Caution

需要注意的四大陷阱

Hallucination

生成不存在的库/函数
→ 确认 import 是否真的能运行

Security

患者数据、基因组数据泄露风险
→ 遵守隐私保护法规、HIPAA

Reproducibility

相同提示词 ≠ 相同结果
→ requirements.txt + 固定 seed

Over-reliance

不理解代码就无法调试
→ 生物信息学基础知识仍然必不可少

Vibe Coding in Action

如何用 Vibe Coding 构建这个流程

# 在 Claude Code 中输入的实际提示词 "我有一个用 REINVENT4 生成的包含 50 个 SMILES 的文件。 请创建一个自动化脚本，用 AutoDock Vina 对这些分子进行对接。 具体要求： 1. 用 RDKit 将 SMILES → 3D 结构转换（ETKDG 方法） 2. 用 Meeko 转换为 PDBQT 格式 3. 运行 AutoDock Vina（exhaustiveness=16） 4. 将结果整理为 CSV（分子名称、Vina score、最优构象） 5. 将前 10 个的结合构象保存为 SDF receptor.pdbqt 已经准备好了。 box center: [16.3, 28.1, 31.4], size: [24, 24, 24]"

→ Claude Code 生成了约 200 行完整的流程脚本

Workflow

完整的 Vibe Coding 工作流程

1. PLAN "要做什么？" 用自然语言整理 ↓ 2. PROMPT 明确意图 + 丰富上下文 + 具体要求 ↓ 3. GENERATE AI 生成代码 ↓ 4. REVIEW 代码正确吗？+ 结果在生物学上合理吗？ ★ 最重要 ↓ 5. ITERATE 提出修改 → 返回第 3 步 ↓ 6. TEST 自动化测试 + 手动验证 ↓ 7. DOCUMENT README、提示词记录、确保可重现性
